1. Keuntungan memisahkan header dan footer menjadi file component tersendiri adalah untuk menerapkan prinsip koding DRY (Don't Repeat Yourself) dan kemudahan pemeliharaan kode (maintainability). Jika terjadi perubahan tampilan atau tautan navigasi pada header dan footer, kita hanya perlu mengubah satu file component saja tanpa harus mengedit setiap halaman satu per satu. Hal ini juga membuat struktur kode halaman utama menjadi lebih bersih, rapi, dan fokus pada konten inti.
 
2. Halaman-halaman admin (Buku, Kategori, Penulis, Pengguna, Profil) mengalami masalah duplikasi kode pada bagian Sidebar (navigasi samping) dan Topbar (bar navigasi atas). Sebelum dipisah, markup HTML untuk sidebar dan topbar ditulis ulang secara identik di 14 file halaman admin, yang menyulitkan perbaikan dan memperbesar risiko ketidakstabilan tampilan antar halaman. Setelah dijadikan component, setiap halaman cukup memanggil require untuk sidebar dan topbar, lalu mengisi variabel seperti $pageTitle dan $pageSubtitle sesuai halamannya. Dengan begitu, perubahan menu atau tampilan bar atas cukup dilakukan di satu tempat dan langsung berlaku di semua halaman admin.
